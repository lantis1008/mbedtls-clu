# `x509` — Certificate Display

Equivalent to a small subset of `openssl x509`. Read-only: parses and
prints fields from an existing certificate. There is no signing,
conversion, or output-writing path in this utility — for issuing or
converting certificates, see [req.md](req.md) or [ca.md](ca.md).

## Synopsis

```
mbedtls-clu x509 [options]
```

## Options

| Flag | Argument | Description |
|---|---|---|
| `-help` | | Display usage summary |
| `-in` | `infile` | Certificate input file |
| `-noout` | | Suppress default output |
| `-text` | | Print the certificate in text form |
| `-serial` | | Print the certificate's serial number |

## Output

Prints whatever combination of `-text`/`-serial` was requested to stdout.
`-noout` suppresses everything except explicitly requested fields. There is
no `-out`/`-outform` — `x509` never writes a file.

## Examples

```sh
mbedtls-clu x509 -in cert.pem -text -noout
mbedtls-clu x509 -in cert.pem -serial -noout
```

## Known differences/gaps vs OpenSSL

Full details in
[`tests/KNOWN_DIFFERENCES.md`](../tests/KNOWN_DIFFERENCES.md). Summary:

- **Only a small subset of `openssl x509`'s surface is supported** — no
  format conversion (`-out`/`-outform`/`-inform`), no signing/self-signing,
  no verification, no fingerprint/hash/dates/extensions display beyond
  `-text`, no `-noout`-independent field flags beyond `-serial`.
- **`-text` output is not line-for-line identical to OpenSSL's own
  `-text`** — by design, this test suite only ever asserts
  semantic/field-content equivalence, never a full-text diff.
